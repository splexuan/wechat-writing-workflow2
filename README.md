# 写作流程 v2

这是一套只负责文字创作的轻量公众号写作 Skill。它把主题、链接、素材或已有草稿推进为文字终稿，不要求每篇文章经过固定九阶段。

## 目录

```text
wechat-writing/     Skill 本体，只保存通用方法
workspace/          私有作者档案、样本、文章项目
```

`workspace/articles/` 用于需要保存或跨轮继续的文章；普通单轮写作可以直接在聊天中完成。`workspace/writing-samples/` 可以放作者本人的代表文章。

首次使用时可将 `author-profile.example.md` 和 `style-lessons.example.md` 分别复制为 `author-profile.md`、`style-lessons.md`。真实作者档案、文章和写作样本已被 `.gitignore` 排除，不应提交到公开仓库。

## 使用示例

- “我想写一篇关于 AI 让人越来越不敢表达的文章，先帮我找方向。”
- “就按你推荐的方向直接写，目标读者是普通职场人。”
- “检查这篇稿子，重点看事实边界和读者会不会中途掉线。”
- “比较我改过的版本，记住可复用的写作偏好。”
- “继续上次那篇文章。”

## 默认行为

- 宽泛主题最多给 3 个方向并推荐一个。
- 明确选题直接写，不强制重复讨论流程。
- 研究只在事实、时效性或风险需要时触发。
- 普通润色默认保留内容；结构重写、自然化和终检按需要分开处理。
- 完整成稿经过事实、论证、读者和语言四层审校。
- `final.md` 是流程终点，不继续执行任何成稿后制作或分发动作。

## 方法参考

入口只判断当前任务需要读什么，具体方法放在 `wechat-writing/references/` 中按需使用：

| 参考 | 解决的问题 |
|---|---|
| `ideation.md` | 宽泛主题怎样形成真正不同的写作方向 |
| `research.md` | 什么需要核实，主张与证据怎样对应 |
| `argument.md` | 怎样形成有边界的中心论点和推进提纲 |
| `article-types.md` | 解释、评论、教程、对比、复盘、随笔分别怎样交付价值 |
| `drafting.md` | 标题、开头、正文推进、段落和结尾怎样写 |
| `revision.md` | 旧稿怎样分层诊断，并选择合适的修改强度 |
| `natural-editing.md` | 怎样去除机器模式，同时保留事实、立场和作者声口 |
| `review.md` | 终稿怎样检查事实、论证、读者理解与语言 |
| `style-learning.md` | 怎样从范文和人工修改中学习长期偏好 |
| `examples.md` | 关键规则的短正反例 |

这些参考综合了旧流程和本地参考 Skills 中可迁移的方法，并重新组织、改写为当前工作流的规则；不把第三方固定公式或大段原文直接拼入项目。自然化编辑不使用词语黑名单、标点禁令或强制口语，而是按事实风险、内容空转、公式结构、表达节奏和作者声口依次处理。

Skill 尚未自动安装到全局目录。可以直接在本项目中使用；若要全局调用，再把 `wechat-writing/` 安装或复制到 Codex Skills 目录。
