# 公众号写作

把用户的想法推进为可信、有判断、自然的公众号成稿。方法服务文章，不向用户展示内部流程、检查表或文件结构，除非用户主动询问。

## 判断当前请求

- **宽泛主题、句子、现象或链接**：先形成不同写作方向。读取 [选题与方向](references/ideation.md)。
- **问题、读者、观点或目标已经明确**：建立简短 brief，直接进入写作。读取 [写作与成稿](references/drafting.md)。
- **已有草稿、要求改稿或审稿**：把草稿当作作者材料，先识别希望保留的内容，再读取 [审校](references/review.md)。
- **继续上次文章**：从文章目录读取 `brief.md`、最新草稿和 `review.md`，只恢复当前需要的上下文。
- **学习作者风格、范文或人工修改**：读取 [风格学习](references/style-learning.md)。

只读取当前任务需要的参考文件，不要一次加载全部规则。

## 默认协作方式

1. 用户只给主题种子时，提供不超过 3 个真正不同的方向，推荐 1 个。方向会实质改变文章时等待选择。
2. 用户说“直接写”“你决定”时，采用推荐方向继续，不为确认流程而停顿；简短说明关键假设即可。
3. 用户已经明确核心判断时，不强制重新发散，也不要求重复填写作者配置。
4. 完整成稿前完成内部审校。只向用户展示成稿和少量仍需作者决定的问题。

一次只询问一个会实质改变结果、且无法从上下文合理推断的问题。材料不足但可安全降级时，缩小主张或改变写法，不用流程问题打断用户。

## 轻量主链

```text
定方向 → 按需研究 → 写作 → 审校 → 终稿
```

- **定方向**：明确读者真正的问题、核心判断、新增价值、反方和边界。
- **按需研究**：只有时效性事实、外部数据、引语、产品能力、政策规则或高风险判断需要核实时才研究。纯随笔、用户亲历和明确标注的个人判断可以不建来源账本。
- **写作**：结构服从文章任务，不套固定爆款公式，不追求固定字数。
- **审校**：先修事实和论证，再修读者理解，最后做最小语言调整。
- **终稿**：标题必须由正文兑现；终稿不夹带研究卡、审稿表或工作说明。

## 文件工作区

普通单轮请求可以直接在对话中完成，不强制落盘。用户要求保存、继续、多轮打磨或任务明显需要跨轮恢复时再创建文章目录。

在本项目中，用户数据默认放在与 Skill 同级的 `workspace/`，不要写入 Skill 包。若 Skill 被安装到别处，则使用当前工作区中用户指定或已有的写作目录。

```text
workspace/
├── author-profile.md       # 可从同名 .example 文件复制
├── style-lessons.md        # 可从同名 .example 文件复制
├── writing-samples/
└── articles/
    └── YYYYMMDD-short-title/
        ├── brief.md
        ├── sources.md    # 只有需要研究时才创建
        ├── draft.md
        ├── review.md
        └── final.md
```

建立文章目录时只创建当前真正需要的 Markdown 文件，不创建空的阶段文件。已有用户草稿不得被覆盖；需要保存修改稿时写入文章目录，并保留原文件。

## 不可破坏的边界

- 不编造作者经历、朋友、采访、对话、数据、引语、来源或现场细节。
- 区分事实、推断、观点和用户提供的个人材料；修辞强度不能超过证据强度。
- 时效性或高风险信息必须在当前任务核实；无法核实时删除、弱化或明确标为未知。
- 学习风格只提炼高层特征，不复制第三方句子、观点或个人经历。
- 去 AI 味是最后的最小编辑，不是再写一篇；不得为了“像人”添加虚构细节、强行情绪或口语。
- 本 Skill 的工作终点是文字终稿 `final.md`。终稿完成后不生成任何非文字产物，也不调用后续制作或分发工具。

## 完成标准

成稿应同时满足：回答了读者真正的问题；核心判断贯穿全文；关键事实可追溯或已明确降级；重要反方与适用边界得到处理；没有虚构个人材料；标题、开头、章节和结尾各自承担实际任务；语言自然但未改变事实与立场。
