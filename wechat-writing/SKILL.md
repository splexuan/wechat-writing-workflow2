# 公众号写作

把用户的想法推进为可信、有判断、自然的公众号成稿。方法服务文章，不向用户展示内部流程、检查表或文件结构，除非用户主动询问。

## 判断当前请求

- **给出新主题、事件、现象、链接或研究问题，但尚未给出中心判断**：评论、解释和热点分析必须先读取 [选题与方向](references/ideation.md)，给出候选、推荐一项并等待选择。问题即使很具体，或使用了“为什么”“探讨一下”“写一篇”等措辞，也不等于方向已经确定；步骤明确的教程、事实整理等非立论任务按其任务直接继续。
- **用户选中了候选方向或继续补充观点，但尚未确认最终中心主题**：继续读取 [选题与方向](references/ideation.md)，与用户收敛文章究竟要主张什么。提出一句最终中心判断并等待明确确认；不得创建 brief、研究、提纲或正文。
- **明确要求直接成稿，但尚未确认中心主题**：可以内部按 [选题与方向](references/ideation.md) 比较方向，但必须把准备采用的中心判断展示给用户并等待确认。“直接写”不能跳过中心主题确认。
- **用户已经明确确认最终中心主题**：先形成最小 brief。评论、解释和热点分析先按 [论证与提纲](references/argument.md) 建立最短论证链，再按 [写作与成稿](references/drafting.md) → [自然化编辑](references/natural-editing.md) → [审校](references/review.md) 完成；教程、复盘和随笔不需要立论时可直接进入写作。用户在同一条请求中给出完整中心判断并明确要求“就按这个判断写”，视为已经确认。
- **事实密集、时效性强或高风险文章**：方向与最小 brief 确定后，按 [研究与证据](references/research.md) → [论证与提纲](references/argument.md) → [写作与成稿](references/drafting.md) → [自然化编辑](references/natural-editing.md) → [审校](references/review.md) 执行。研究不得先于选题，也不得脱离 brief 漫游。
- **公共议题或热点分析，且希望传到作者读者圈之外**：在上述流程之外，写作前额外读取 [锐化手法](references/sharpening.md)，用真实存在的预设和可查专名替代抽象判断；个人随笔、复盘和教程不读取。
- **文体确实不清楚**：写作前读取 [文体选择](references/article-types.md)，选定一种主任务后不再反复切换。
- **已有草稿，需要重新立论、调整结构或大幅增删**：读取 [改稿](references/revision.md) → [自然化编辑](references/natural-editing.md) → [审校](references/review.md)。
- **已有文字，只要求局部润色、去 AI 味、更自然或像作者本人**：读取 [自然化编辑](references/natural-editing.md) → [审校](references/review.md)，不因“已有草稿”额外加载结构改稿。
- **只要求校对、审稿或最终检查**：读取 [审校](references/review.md)。
- **要求事实检查、来源核验或更新时效信息**：按 [研究与证据](references/research.md) → [审校](references/review.md) 执行；只修改证据不支持或已经过时的部分，不把核查扩成无关重写。
- **继续上次文章、保存跨轮状态或管理作者资料**：先读取 [工作区与恢复](references/workspace.md)，按其中的路径解析和恢复顺序执行，再加载当前任务需要的写作参考。
- **学习作者风格、范文或人工修改**：读取 [风格学习](references/style-learning.md)；需要长期保存时同时读取 [工作区与恢复](references/workspace.md)。
- **规则仍难以判断或需要看正反例**：再读取 [判断示例](references/examples.md)，不默认加载。

只读取当前任务需要的参考文件，不要一次加载全部规则。

一个请求同时涉及多种修改时，按“结构与内容 → 自然化 → 终检”的顺序各执行一次。凡本 Skill 新生成完整成稿或完成全文改稿，自然化都是必经步骤；仅做事实核查、校对或局部修改时不扩大范围。普通“润色一下”默认只改善表达并保留内容。

## 默认协作方式

1. 新文章只有主题、热点、现象或研究问题而没有中心判断时，提供不超过 3 个问题和结论真正不同的方向，推荐 1 个并停止，等待用户选择。
2. “为什么会这样”“探讨一下这个现象”“围绕它写一篇”只定义了研究范围，不代表用户选定了角度或结论。
3. 选中方向只代表选择探索路线，不代表中心主题已经确定。继续讨论要回答的问题、核心判断、关键词含义、竞争解释和边界。
4. 把收敛后的一句中心判断展示给用户并停止。只有用户明确表示认可，才能形成 brief、研究、提纲或正文；用户继续补充观点时，应再次整合并确认。
5. “直接写”“不要给方向”只能跳过候选展示，不能跳过中心主题确认；用户已在同一条请求中明确给出最终判断并要求按它写时例外。
6. 中心主题确认后先形成最小 brief。评论和分析先写出最短论证链与唯一主解释，再决定是否研究；研究问题必须来自会影响结论的主张。
7. 数据、案例和背景进入正文前必须说明它承担的论证职责；“真实、有趣、已经查到”都不是保留理由。删除后不影响理解、可信度或边界的材料不写。
8. 新成稿和全文改稿必须做一轮删除式压缩，再完成审校。重要机制和关键反方讲透，次要背景、重复例子和无关延伸点到为止或删除。
9. 默认只交付成稿和少量必须由作者决定的问题，不展示内部流程或长篇修改说明。

一次只询问一个会实质改变结果、且无法从上下文合理推断的问题。材料不足但可安全降级时，缩小主张或改变写法，不用流程问题打断用户。

## 轻量主链

```text
选择方向 → 讨论并确认中心主题 → 最小 brief 与最短论证链 → 材料准入与按需研究 → 写作或改稿 → 删除式压缩 → 审校 → 终稿
```

- **选择方向**：主题种子先形成真正不同的候选；用户选择后只锁定探索路线，不立即进入后续阶段。
- **确认中心主题**：与用户把暂定观点收敛为一句可论证、有边界的中心判断；展示并获得明确确认，这是写作前的 STOP。
- **最小 brief 与最短论证链**：锁定读者问题、核心判断、唯一主解释、最少需要完成的推理步骤、竞争解释、适用边界和作者原文的进入速度；后续研究与正文不得悄悄换题或把每句话扩成一节。
- **材料准入与按需研究**：只有能承担核心前提、关键证据、必要解释、强反例或适用边界的材料才进入正文。只有时效性事实、外部数据、引语、产品能力、政策规则或高风险判断需要核实时才研究；研究结果是备选材料，不是正文配额。
- **写作**：围绕最短论证链组织材料，评论和分析只展开一条主解释；其他解释只能补缺口、施加压力或限定边界。不套固定爆款公式，不追求固定字数。
- **删除式压缩**：先删无职责段落、重复结论、同层例子、多余比喻和不承重解释，再修改仍有必要的句子；保留事实、立场、必要限定与作者声口，不靠虚构细节制造人味。
- **审校**：旧稿先诊断再修改；终检先查事实和论证，再查读者理解，最后做最小语言调整。
- **终稿**：标题必须由正文兑现；终稿不夹带研究卡、审稿表或工作说明。

## 文件工作区

普通单轮请求可以直接在对话中完成，不强制落盘。用户要求保存、继续、多轮打磨或任务明显需要跨轮恢复时再创建文章目录。

需要落盘时，先按 [工作区与恢复](references/workspace.md) 解析写作工作区。不要用相对 Skill 安装目录的路径保存用户数据，也不要把作者资料、样本或文章写进 Skill 包。

```text
workspace/
├── author-profile.md       # 从 Skill 的 assets 模板复制
├── style-lessons.md        # 从 Skill 的 assets 模板复制
├── writing-samples/
├── active-article.md       # 仅跨轮文章存在时使用
└── articles/
    └── YYYYMMDD-short-title/
        ├── brief.md
        ├── sources.md    # 只有需要研究时才创建
        ├── draft.md
        ├── review.md
        ├── final.md
        └── versions/     # 只有实质重写且需要保留旧稿时创建
```

模板随 Skill 放在 `assets/`，只在需要相应文件时复制。建立文章目录时只创建当前真正需要的 Markdown 文件，不创建空的阶段文件。已有用户草稿不得被覆盖；需要保存修改稿时写入文章目录，并保留原文件。

## 不可破坏的边界

- 不编造作者经历、朋友、采访、对话、数据、引语、来源或现场细节。
- 区分事实、推断、观点和用户提供的个人材料；修辞强度不能超过证据强度。
- 时效性或高风险信息必须在当前任务核实；无法核实时删除、弱化或明确标为未知。
- 学习风格只提炼高层特征，不复制第三方句子、观点或个人经历。
- 去 AI 味是最后的最小编辑，不是再写一篇；不得为了“像人”添加虚构细节、强行情绪或口语。
- 本 Skill 的工作终点是文字终稿 `final.md`。终稿完成后不生成任何非文字产物，也不调用后续制作或分发工具。

## 完成标准

成稿应同时满足：兑现 brief；核心判断有一条可复述的最短论证链；每项数据、案例和背景都有明确职责；正文只展开一条主解释；并列章节处于同一逻辑层级且各有职责；关键事实可追溯或已降级；没有虚构个人材料；结尾不开新议题；已完成删除式压缩；重要内容讲透，次要内容不展开；语言自然且未改变事实与立场。
