# 风格学习

用于作者初始化、参考文章、人工修改和长期偏好。目标是减少重复沟通，不是用固定人设覆盖本次文章。

## 优先级

发生冲突时依次服从：

1. 用户本次明确要求；
2. 本次文章的事实、体裁和目标读者；
3. 当前草稿已经形成的有效声音；
4. `author-profile.md` 中用户确认的偏好；
5. `style-lessons.md` 中适用于当前范围的稳定规则；
6. 参考文章的高层风格特征；
7. 通用默认值。

不要为了保持“人设”牺牲事实、清晰度或题材适配。

本文件学习的是用户明确希望保留的个人风格，不负责决定默认作者姿态。用户没有明确要求仿写本人时，不从聊天片段、临时口癖、错漏或单次改写中推断其说话方式；评论、随笔和一般解释仍使用 [写作与成稿](drafting.md) 规定的“平视型观察者”姿态。姿态规定作者如何面对读者，风格才涉及措辞、节奏、幽默和个人表达，两者不要混为一谈。

## 作者档案

用户愿意长期保存偏好时，先按 [工作区与恢复](workspace.md) 确定写作工作区，再更新其中的 `author-profile.md`。只记录会改变写作决策的信息：账号定位、主要读者、常见题材、期望声口、内容边界、偏好与反感、第一人称使用范围、真实个人材料的授权方式。

文件不存在时，从 Skill 包内的 `assets/author-profile.template.md` 复制到已确定的写作工作区后再填写；不要把私人信息写回模板或 Skill 包。

缺少档案不是阻断项。用户要求直接写时使用当前上下文，不进行完整问卷。

## 从范文学习

一次最多选择少量最相关样本，提炼：

- 进入问题的速度与方式；
- 句段节奏和信息密度；
- 观点、解释、故事和例子的比例；
- 小标题与结尾习惯；
- 情绪强度、幽默和专业术语使用；
- 作者明确不喜欢的模式。

用户本人作品也只提供风格和结构参考，其中的个人经历不能自动搬到新文章。第三方范文不得复制原句、观点、比喻、故事或辨识度很高的表达。

先形成临时“风格指纹”，再判断是否值得长期保存：

```text
进入方式：直接判断 / 场景 / 问题 / 事实
推进习惯：解释密度、例子位置、是否常处理反方
句段节奏：长短变化、段落密度、列表使用
声口：克制 / 锋利 / 温和 / 幽默，以及适用题材
边界：明确避免的表达和不能迁移的个人内容
```

只提炼能指导决策的特征。“有温度、有深度、自然流畅”过于抽象，不能单独作为规则。

## 从人工修改学习

对比原稿和用户修改稿，记录有意义的变化及最窄适用范围：

```text
规则：教程说明段每段只处理一个操作
范围：文章类型 = 教程
证据：本次人工修改
状态：soft
```

- 单次修改默认是 `soft`，只作为相似任务的参考。
- 同一范围内重复出现至少两次，或用户明确说“以后都这样”，才升级为 `stable`。
- 结构、标题和语气偏好优先限定到具体题材或文章类型，不轻易设为全局规则。
- 新修改与旧规则冲突时，以用户本次选择为准；不要默默同时保留互相矛盾的规则。
- 用户说“这次例外”时不沉淀。

将规则写入已确定写作工作区的 `style-lessons.md`，不要写回 Skill 包。

文件不存在时，从 Skill 包内的 `assets/style-lessons.template.md` 复制；模板只保留空白结构。

## 使用稳定规则

开始写作前，只选择与当前题材、结构或声口匹配的少量稳定规则。软规则不能覆盖本次材料和明确要求。最终文章若因套用偏好而显得刻意，应放弃该规则，并在用户要求复盘时记录原因。

稳定规则也应允许失效：题材变化、用户明确改口或连续两次被人工修改推翻时，降级、缩小范围或删除，而不是不断追加例外。
