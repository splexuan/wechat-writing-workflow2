# 论证与提纲

用于评论、解释、热点分析和需要深度改稿的文章。目标是围绕一个真实问题组织事实、解释和作者判断，而不是把资料依次排进章节。教程、操作指南、单纯叙事和随笔只有在确实需要立论时才读取本文件。

## 中心论点测试

合格的中心论点通常是一句完整判断，并同时满足：

- 回答读者真正的问题，不只是复述主题；
- 有人可能合理地不同意，因此需要论证；
- 对象、时期、条件和确定性与证据相称；
- 能统领全文，能判断每一节为什么存在；
- 提供新增解释、判断标准、被忽略的代价或更准确的边界。

“本文讨论人工智能对写作的影响”是主题；“生成工具降低了成稿成本，但把写作者的稀缺能力推向选题、判断与核验”才是可论证的判断。

如果一句话只能靠“所有人、必然、彻底、颠覆”等词显得有力，先检查是否应缩小范围。

## 论证简报

写提纲前在内部回答：

1. 读者现在可能怎么理解这件事？
2. 本文准备改变哪一个判断？
3. 支撑中心论点的 2—4 个分论点是什么？
4. 每个分论点分别依赖事实、机制、案例还是价值判断？
5. 最强竞争解释是什么，它解释得比本文更好的部分有哪些？
6. 中心论点在哪些条件下不成立？
7. 读完后，读者获得的是新事实、解释模型、选择标准还是表达自己感受的语言？

这些内容用于组织写作，不要把问题清单原样放进正文。

## 搭建主张链

每个关键段落尽量完成一种清晰关系：

```text
材料或现象 → 解释 → 中间判断 → 对中心论点的作用
```

检查容易跳步的位置：

- 从“同时发生”跳到“前者导致后者”；
- 从“能做到”跳到“会普遍采用”；
- 从“一个案例”跳到“一类人都如此”；
- 从“描述现状”跳到“因此应该怎样”；
- 从“某方有动机”跳到“某方一定出于该动机”。

需要补证就回到研究；缺乏材料时，改成可能性、条件式判断或开放问题。

## 认真处理反方

反方不是为了让文章显得客观而插入的一句“当然也有人认为”。优先寻找：

- 能解释同一批事实的另一套机制；
- 结论相反但证据质量相当的材料；
- 文章结论不适用的人群、时期或场景；
- 即使中心判断成立，也必须付出的代价。

处理反方有四种诚实结果：吸收进主论点、限定结论、说明为何证据仍不足，或承认文章当前无法裁决。不要制造一个明显愚蠢的观点再轻易驳倒。

## 原创性从哪里来

不必故意反常识。可用的新增价值包括：

- 把几个零散事实放进同一个因果或激励框架；
- 指出常见说法成立所缺少的条件；
- 区分经常被混为一谈的对象、时间尺度或评价标准；
- 找到被多数讨论忽略的成本、受影响者或二阶后果；
- 把抽象争论还原成读者可使用的判断标准；
- 用真实个人材料说明一种体验，但不把它外推为普遍规律。

若没有新增价值，宁可做清楚的事实梳理或实用指南，不强造惊人结论。

## 把论证变成提纲

提纲不是资料分类。每一节用一句“本节完成什么推进”来命名：

| 位置 | 要完成的任务 |
|---|---|
| 开头 | 建立具体问题、冲突或需要修正的理解 |
| 第一推进 | 给读者理解后文所需的事实或概念 |
| 核心推进 | 展开最关键的机制、证据或判断 |
| 压力测试 | 处理竞争解释、反例、代价或边界 |
| 结尾 | 回答最初问题，并给出与题材相称的读者收益 |

不必每篇都有五部分，也不要求按这个顺序。判断每一节：删掉后，中心论点会失去哪一环？若答案只是“少一点丰富”，该节可能只是旁枝。

若主文体尚未确定，再读取 [文体选择](article-types.md)；已经明确是评论或解释文章时，直接进入 [写作与成稿](drafting.md)，不要在两个参考之间往返。
