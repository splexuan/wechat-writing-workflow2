# 写作与成稿

用于明确选题后的 brief、按需研究、结构设计和正文写作。目标是解决一个读者问题，不是完成固定阶段或凑齐模板字段。

## 建立最小 brief

写正文前在内部明确；需要跨轮保存时写入 `brief.md`：

- 目标读者与阅读情境；
- 读者真正的问题；
- 核心判断；
- 相比常见说法新增什么；
- 最强反方或替代解释；
- 判断成立的条件与边界；
- 用户明确提供的个人材料；
- 必须包含、必须避免和需要核实的内容。

核心判断应是可以讨论和论证的句子，不是主题复述或“本文将介绍”。找不到可靠的新角度时，缩小问题、补充条件或提供判断框架，不强行反转。

## 决定是否研究

以下内容进入正文前需要核实：近期事件、日期、数字、引语、研究结论、产品能力、价格、政策、法律、医疗、金融、安全、排名和具体归因。

来源优先级：原始文件、官方页面、论文或公开数据；其次是能回到原始材料的可靠解释。社区讨论用于发现问题和反方，不能单独证明普遍事实。搜索摘要和模型记忆不是证据。

研究型文章可用 `sources.md` 记录少量关键主张：

| 主张 | 类型 | 来源 | 状态 | 边界 |
|---|---|---|---|---|
| 正文准备表达的内容 | fact / inference / opinion / personal | 链接或用户材料 | verified / bounded / unsupported | 证据最多支持到哪里 |

- `fact` 需要直接来源。
- `inference` 写清依据与不确定性。
- `opinion` 不伪装成共识。
- `personal` 只能来自用户本次明确提供或确认的材料。
- `unsupported` 不进入正文；优先补查，其次缩小、改成条件式判断或删除。

随笔、叙事和纯经验文章若不依赖外部事实，不必为了形式创建来源账本。

## 选择结构

结构服从文章任务。常见选择包括：

- **痛点解法**：具体摩擦 → 常见做法为何失效 → 方法与条件 → 验证和避坑。
- **解释分析**：现象 → 真正问题 → 机制 → 竞争解释 → 暂时判断 → 现实影响。
- **纯观点**：明确命题 → 常见看法 → 证据与推理 → 最强反方 → 成立边界。
- **对比决策**：读者选择 → 比较标准 → 权衡 → 按条件推荐 → 不适用情况。
- **故事或复盘**：真实背景 → 选择与代价 → 转折 → 结果 → 可迁移判断。
- **热点解读**：发生了什么 → 为什么现在发生 → 影响谁 → 容易误读什么 → 后续信号。

这些是可选骨架，不是固定模板。每一节只承担一个推进任务；小标题表达该节真正增加的判断，不写“背景介绍”“具体分析”之类空标题。

## 写初稿

- 开头尽快建立读者问题、冲突或核心判断；场景必须来自真实材料或被明确标成假设。
- 先讲清楚，再追求金句。事实回答“发生了什么”，机制回答“为什么”，影响回答“这改变了谁的什么”。
- 因果链较长时逐步展开，区分已知、推断和未知。
- 一段只承担一个主要任务，但不机械限制句数和段落长度。
- 标题、小标题和段落都要兑现信息，不依靠空洞情绪维持吸引力。
- 读者收益随题材变化：工具文可以给决策标准，评论文讲透机制，复盘文讲清事实线与影响，随笔可以提供更准确的感受或看法。不要统一强塞清单和行动号召。
- 没有作者经历时，可以写第一人称判断，不能补写第一人称事件、朋友同事、对话和感官细节。

## 保存规则

- 用户提供的原稿保持原样，不覆盖。
- 初稿写入 `draft.md`；完整审校后的文字写入 `final.md`。
- 只有实质重写且用户希望保留历史时，才创建 `versions/` 保存旧稿；普通小改不制造版本噪音。
- `final.md` 是本 Skill 的最终交付。除非用户重新要求编辑文字，完成后不再触发其他步骤。

初稿完成后转入 [审校](review.md)。
